# AudioRouter

把**一台电脑的音频同时播到多个输出设备**的轻量桌面工具（WinUI 3 + Rust 原生实现）。

比如：笔记本的同一个音乐，同时输出到客厅音箱、书房音箱和蓝牙耳机。

## 能做什么

- 把一个音频输出设备的音频**同时**路由到其他多个输出设备
- 实时列出系统音频设备，热插拔的设备即时出现
- 每个输出设备都能单独「试听」，帮你确认哪个是哪个音箱
- 每个输出设备可单独选择声道模式（立体声 / 左单声道 / 右单声道 / 单声道 / 左右互换 / 仅左 / 仅右）
- 托盘常驻，托盘菜单实时显示当前路由状态，「显示 / 隐藏」是真切换
- 可自定义全局热键（留空表示不注册），按下热键随时唤出控制面板
- 关闭控制面板窗口只是隐藏到托盘，托盘、路由与热键继续在后台运行
- 记住窗口位置、大小与侧栏展开状态，下次启动自动恢复
- 首次启动按系统 UI 语言自动选择中文 / 英文，之后可在设置里随时切换
- 支持开机自启（自启时只驻留托盘与路由，不加载图形界面）

## 系统要求

- Windows 10 1809（1809 及以上）或 Windows 11，**64 位**
- 选「自包含」安装包的话无需另外安装任何运行库

## 下载与安装

在 [Releases](https://github.com/fangfuzha/AudioRouter/releases) 页面下载安装包，有两个版本：

| 版本 | 文件名 | 大小 | 适合谁 |
|---|---|---|---|
| **自包含**（推荐） | `AudioRouter-Setup-<版本>-x64.exe` | 约 16 MB，含整套运行库 | 大多数用户 —— 装完即用，不需要装别的东西 |
| **框架依赖** | `AudioRouter-Setup-<版本>-x64-fd.exe` | 约 4 MB，只含引导程序 | 电脑上已经装好 Windows App Runtime（企业统一分发运行时等场景） |

- 两个安装包**功能完全一样**，只是运行时来源不同；不确定就选自包含。
- 它们**共用同一个 AppId、互斥覆盖**：装了一个再装另一个会替换掉前者，不会并存。
- 安装过程提供中文 / 英文向导，会创建开始菜单快捷方式，可选桌面快捷方式。
- 之后可以在「控制面板 → 程序」里一键卸载。

## 使用

1. 启动后应用会常驻系统托盘（控制面板默认会打开，也可以从托盘图标唤出）。
2. 在控制面板里选一个**源设备**（要播出的那个输出设备），再勾选若干**目标设备**。
3. 点「开始路由」，声音就同时从所有勾选的设备出来。
4. 对着某个目标设备点「试听」，用耳朵确认它到底是哪台音箱。
5. 需要时调整每个目标设备的声道模式，或在设置里绑定全局热键。

路由在后台持续生效：拔掉一个设备会自动重试，重新插上后不用重启应用。

## 常见问题

**Q：点「开始路由」没声音？**
先确认源设备里本来就有声音（用系统音量条试一下），再逐个试听目标设备 —— 有时是选错了设备或某个设备被静音/独占。

**Q：框架依赖版启动时弹出了「安装 Windows App Runtime」的官方界面？**
说明系统上还没有该运行时，按提示点「安装」即可；或者干脆换用自包含安装包。

**Q：控制面板窗口关掉后程序还在吗？**
默认行为是「关窗口 = 隐藏到托盘」，托盘、路由与热键继续运行。要让关闭窗口即退出程序，去设置里关闭「关窗口时隐藏到托盘」。

**Q：路由中途断掉了？**
多半是设备热插拔或音频格式变了，应用会自动重试。仍然不行就看一下日志：
`%LOCALAPPDATA%\AudioRouter\logs\AudioRouter.log`（超过 5 MiB 会自动滚动为 `.old`）。

**Q：能自动升级吗？**
能。程序会定期检查新版本并提示更新，下载完成后静默安装并重启。**更新会沿着你当前这条安装包路线走**：自包含版本升级后仍是自包含，框架依赖版本升级后仍是框架依赖，不会互相替换。
